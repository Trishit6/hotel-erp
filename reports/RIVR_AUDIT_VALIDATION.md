### 3.1 API Endpoint Registration

| Module | Endpoints (method) | Auth Required |
|--------|-------------------|--------------|

| public | Various guest-facing routes | Varies |

### 3.2 Authentication Requirements

- **`/api/auth/login`**: Requires valid credentials (email + password). Rate-limited.
- **`/api/auth/me`**: Requires session cookie (`credentials: "include"`).
- **`/api/auth/setup`**: Requires `SETUP_TOKEN` from `.env` + advisory locking. **Only one Super Admin allowed.**
- **`/api/admin/*`**: All require `requireAuth` + specific permissions via `hasPermission(role, permission)` from `services/permissions.ts`.
- **Permission checks** are enforced server-side. The frontend `StaffChrome.tsx` also filters navigation using `can(item.roles)`, but the authoritative enforcement is backend.

### 3.3 Service → MariaDB Queries

Service layer queries (from source inspection):

- **`users.ts`**: `createUser()` inserts into `users` table with Argon2id hash; `login()` validates `passwordHash`; `findUserByEmail()` selects by email.
- **`settings.ts`**: `ensureSettingsRow()` selects/inserts into `system_settings`; `updateSettings()` updates with `updatedBy: actor.id`, `updatedAt: new Date()`.
- **`reports.ts`**: `getDashboard()` queries `rooms`, `guests`, `invoices` tables with aggregate SQL (`sum(case...)`), `count(*)`.
- **`reservations.ts`**: Full CRUD with room locking `.for("update")`, overlap checking, status transitions.
- **`housekeeping.ts`**: `createTask()` inserts into `housekeepingTasks`; `updateTask()` updates with optional `taskType`, `dueDate`, `completionNotes`.
- **`inventory.ts`**: `createInventoryItem()` inserts into `inventory`; now includes `sku` field.
- **`restaurant.ts`**: `listMenu()` queries `restaurantMenuCategories` and `restaurantMenuItems` (tables that do NOT exist in the current DB).
- **`permissions.ts`**: `PERMISSIONS` catalogue and `hasPermission()` function — authoritative RBAC enforcement.

### 3.4 Response Matching Frontend Expectations

Based on mapper inspection (`services/mappers.ts`):

- `mapRoomType`, `mapRoom`, `mapGuest`, `mapReservation`, `mapInvoice`, `mapOrder` — all return objects matching the TypeScript interfaces in `hotel-data.ts`.
- `mapMenuCategory`, `mapMenuItem` — new mappers for the restaurant menu tables.
- `mapSettings`, `mapTask` — updated to include new fields (taskType, dueDate, completionNotes, invoiceFooter, etc.).
- `mapInventory` — now includes `sku`.

**Consistency:** The mapper outputs match the TypeScript interfaces when the corresponding database rows exist. Since the DB has 0 records in business tables, no mapper output was verified at runtime.
